# Mayhem Pocket 설계

## 목적과 사용 환경

Windows 10, RAM 16GB, Chrome, 4K 화면·150% 배율의 단일 모니터에서 게임 중 잠깐 검색하는 개인용 아수라장 참고 도구다. 광고, 추적 스크립트, 게임 연동, OCR, 오버레이 없이 필요한 데이터만 표시한다. 코드는 공개하고 API 키와 내려받은 데이터·이미지·개인 백업은 공개하지 않는다.

## 기술 구성

- React, TypeScript, Vite
- shadcn/ui, Tailwind CSS, 다크 테마
- Node.js, Fastify 로컬 서버
- 버전별 JSON 파일 및 이미지 캐시, 첫 버전은 DB 불필요
- Windows 배포본에 호환되는 Node 런타임 포함. 개발·빌드는 Node 설치 환경에서 수행한다.
- 개발 중 Vite 서버와 API 서버를 사용하고 배포 시 Fastify가 빌드된 정적 화면과 API를 함께 제공한다.

## 화면과 기능

기본 화면은 작은 헤더와 검색창, 즐겨찾기, 최근 조회, 챔피언 자체 티어 목록으로 구성한다. 소개 문구는 유지하고 목록 갱신과 전체 증강 받기는 항상 노출한다. 그 외 데이터 관리는 기본으로 접는다. 목록에는 아이콘·이름·티어만 표시한다. 이름·초성·영문 별칭 검색을 지원한다. 실제 Chrome CSS viewport에 맞춰 반응형으로 배치하며 물리 해상도 3840px를 화면 너비로 가정하지 않는다.

챔피언 상세는 `빌드` 요약 → `증강 순위` → `아이템 빌드` 순서의 탭으로 구성한다. 새 기본 탭은 빌드 요약이며 기존에 저장한 상세 탭 선택은 유지한다. 요약에는 추천 rank 기준 상위 증강 10개와 기본 정렬 빌드의 핵심 아이템 조합 최대 3개를 각각 이미지 한 줄로 표시한다. 넓은 화면에서는 증강을 5개씩 두 열로 배치하고 아래에 핵심 빌드 조합 3줄을 표시한다. 요약은 상세 탭의 필터·정렬과 독립적으로 계산하고 추가 API 요청을 하지 않는다. 요약 증강에는 순위·아이콘·이름·등급만 표시하고 승률·표본은 증강 순위 탭에 유지한다. 챔피언 승률은 상세 확인 버튼 옆에 표시하며 자체 티어는 목록에서만 표시한다. 출처·버전은 접힌 데이터 정보에 모은다. 마지막 챔피언·탭·필터를 기억한다. 검색 단축키 `/`는 입력창 바깥에서만 동작하며 Escape로 검색을 해제한다. 검색과 필터링은 저장된 데이터를 사용한다.

증강은 API rank 오름차순이 기본이다. 등급 필터, 이름·초성 검색, 승률순 전환을 제공한다. 승률, 표본 수, 출처를 함께 표시한다. 미제공 값은 0으로 바꾸지 않고 정보 없음으로 표시한다. 승률순은 유효 값만 정렬하고 누락 값은 마지막에 둔다.

빌드는 사용 빈도순을 기본으로 한다. 빌드 유형별 코어 아이템, 후속 아이템, 소환사 주문, 스킬 순서를 표시한다. 승률 정렬 시 표본 수를 함께 노출한다. 일반 칼바람 빌드도 참고 자료로 허용한다는 사용자 결정을 반영한다. 아수라장 전용 통계라고 단정하지 않는다.

## 데이터와 검증

ARAMGG 한국어 API를 사용한다. 챔피언 승률, 증강 추천 순위, 업로드 표본 승률, 빌드는 출처가 다를 수 있으므로 provenance를 보존한다. tier 숫자의 의미는 별도 확인 전 임의로 S~D로 변환하지 않는다. 패치는 원본 표기를 보존한다.

블라디미르 상세 실측: 증강 120개, 조합 5개, 빌드 3개. 최상위 items는 비어 있어도 builds 안에 아이템이 있다. 일부 winRate는 음수이며 일부 값은 wins/games와 일치하지 않는다. 범위를 벗어난 값을 승률로 노출하거나 wins/games로 조용히 대체하지 않는다. 불일치는 기록하고 해당 승률은 숨긴다. 비교 시 API 반올림을 고려한다.

원시 champion-augments/8.json도 1 credit으로 확인했다. 응답은 4열 tuple이고 stats_json에 augments, augment_trios 등이 있다. 상세 응답의 builds까지 이 원시 요청에 포함된다고 가정하지 않는다.

## 다운로드와 캐시

config.json은 무료로 버전을 확인한다. 실행할 때 한 번 확인하고 상시 폴링하지 않는다. 갱신은 사용자 버튼으로 수행하며 버전과 예상 credits를 표시한다.

전체 원시 증강 통계와 챔피언·증강 목록은 문서상 173명 기준 175 credits다. 챔피언 수에 따라 비용을 계산한다. 빌드 상세는 조회한 챔피언부터 2 credits로 받아 캐시하는 방식을 기본으로 한다. 무료량 안에 전체 상세가 들어간다고 가정하지 않는다. 동일 버전 상세는 재사용한다.

실제 credit 응답 헤더로 잔량을 갱신한다. 로컬 사용 기록은 계정 전체 잔량의 보장이 아니므로 헤더가 우선이다. 초기 수집은 하루 예산 일부를 상세 조회용으로 남기고 재개 가능하게 한다. 분당 60회 이내로 순차·제한된 다운로드를 수행한다. 429면 중단하고 다음 초기화 이후 수동 재개한다. 자동 추가 결제·유료 전환 기능은 구현하지 않는다.

다운로드는 임시 디렉터리에 저장하고 구조 검증 후 현재 버전 포인터를 교체한다. 실패해도 기존 캐시를 유지한다. 버전이 바뀌었을 때 이전 상세는 구버전 표시를 붙여 볼 수 있게 한다. 데이터가 없으면 다운로드 안내를 표시한다. 오프라인에서도 캐시 조회는 가능하다.

아이콘은 화면에 필요한 것부터 내려받아 파일로 캐시한다. 작은 크기로 표시하고 지연 로딩하며 실패 시 기본 아이콘과 이름을 보여준다. 외부 이미지 URL은 신뢰할 수 있는 HTTPS 호스트 목록으로 제한하고 임의 URL 프록시로 사용되지 않게 한다.

## 쉽게 실행하고 종료하기

Windows 배포본의 실행.cmd 더블클릭으로 내장 Node 서버를 시작하고 기본 브라우저를 연다. 중복 실행 시 기존 정상 서버를 확인하고 화면만 연다. 포트 충돌 시 다른 빈 loopback 포트를 선택한다. Chrome 미설치·경로 차이는 기본 브라우저 열기로 대응한다.

화면 상단에 명확한 종료 버튼을 둔다. 종료하면 진행 중 갱신을 안전하게 취소하고 서버 프로세스를 종료한다. 브라우저 탭 자동 닫기는 보장하지 않으며 화면에 종료 완료를 표시한다. 브라우저를 먼저 닫아도 종료할 수 있도록 종료.cmd도 함께 배포한다. 실행 창을 닫는 동작의 프로세스 정리도 Windows에서 검증한다.

종료 명령은 이 앱이 생성한 프로세스만 대상으로 한다. node.exe 전체 종료 같은 방식은 사용하지 않는다. 저장한 PID만 믿지 않고 앱 인스턴스 식별과 실행 경로를 확인한다. 배포 폴더 이동, 중복 실행, 남은 잠금 파일을 처리한다.

## GitHub Release와 Windows 배포

GitHub Releases에서 실행용 ZIP을 다운로드할 수 있도록 한다. 버전 태그는 v0.1.0 형식을 사용하며 첫 배포는 집 PC에서 검증할 사전 릴리스로 제공한다. 릴리스 노트에는 변경 사항, 최초 API 키 설정, 실행·종료 방법, 업데이트 방법, 알려진 제한 사항을 적는다.

GitHub Actions의 Windows runner에서 타입 검사·관련 테스트·프로덕션 빌드·패키징을 수행한다. 일반 코드 검증과 릴리스 게시 단계를 구분하고, 버전 태그를 기준으로 검증을 통과한 ZIP을 Release 자산으로 게시한다. 빌드에 개인 ARAMGG 키는 필요하지 않게 하며 API 테스트는 fixture를 사용한다. 게시 작업에만 contents: write 권한을 부여한다.

자산 이름은 mayhem-pocket-v0.1.0-windows-x64.zip 형식이다. ZIP에는 빌드된 화면·서버, Windows 10 호환성을 검증한 Node 런타임, 실행.cmd, 종료.cmd, .env.example, 사용 안내와 필요한 제3자 라이선스 고지를 포함한다. 패키징은 명시적인 파일 목록으로 수행하고 실제 .env, 개인 설정, 통계·이미지 캐시, 로그, 백업, 개발 의존성은 포함하지 않는다. ZIP의 SHA-256 체크섬도 함께 제공한다.

사용자는 ZIP을 내려받아 압축을 풀고 최초 한 번 .env에 자신의 API 키를 저장한 뒤 실행.cmd를 더블클릭한다. 별도 Node 설치나 npm install 없이 실행 가능해야 한다. GitHub가 자동 생성하는 소스 코드 ZIP과 실행용 ZIP의 차이를 다운로드 안내에 명시한다.

프로그램 파일과 사용자 파일을 분리한다. runtime/과 app/은 교체 가능한 프로그램 영역이고 .env, cache/, logs/는 사용자 영역이다. 배포 ZIP은 사용자 영역을 덮어쓰는 파일을 포함하지 않는다. 업데이트할 때 앱을 종료하고 기존 폴더의 runtime/과 app/, 실행·종료 스크립트만 새 버전으로 교체하도록 안내한다. .env와 cache/는 유지하며 캐시 형식 변경 시 호환성 검사와 안전한 재생성을 제공한다. 첫 버전에는 자동 업데이트를 넣지 않는다.

릴리스 게시 성공과 Windows 10 실사용 검증 완료는 구분한다. CI 환경에서 통과했다고 집 PC 호환성이나 메모리 사용량을 검증했다고 표시하지 않는다.

## 보안과 공개 저장소

서버는 127.0.0.1에만 바인딩한다. 브라우저 번들·응답·로그에 API 키를 포함하지 않는다. VITE_ 환경변수에 키를 넣지 않는다. 갱신·종료 등 변경 요청은 POST로 처리하고 Origin/Host 및 세션 토큰을 검증해 다른 웹사이트에서 로컬 서버를 조작하지 못하게 한다. API 키는 .env에서만 읽는다.

원격 설명에 포함된 HTML 유사 태그는 그대로 삽입하지 않고 안전한 텍스트/허용된 렌더링으로 처리한다. 다운로드 데이터·아이콘은 Git 제외, .env.example만 공개한다. README에 ARAMGG 출처와 Riot 비공식 고지를 포함한다. 공개 재배포 권한을 포괄적으로 확보했다고 표현하지 않는다.

## 완료 검증

- 블라디미르 기준 추천 순위, 필터, 빌드와 데이터 출처 확인
- 누락·음수·불일치 승률 처리 확인
- 캐시가 있으면 조회 중 API 요청이 발생하지 않는지 확인
- 오프라인·429·중간 실패 시 캐시 보존과 재개 확인
- Windows 10에서 런타임 별도 설치 없이 실행, 중복 실행, 종료 확인
- 실행용 ZIP에 API 키·개인 파일이 없는지, 체크섬과 필수 실행 파일이 포함되는지 확인
- 이전 버전에서 프로그램 파일만 교체했을 때 API 키와 캐시가 유지되는지 확인
- Chrome 150% 배율과 작은 창에서 검색·탭·아이콘 가독성 확인
- 서버 및 Chrome 탭 메모리를 구분해 유휴·조회 중 사용량 측정. 측정 전 절감 수치를 약속하지 않는다.

## 구현 순서

1. 서버·화면 골격, 데이터 계약 및 이상값 처리

3. 챔피언 검색·증강 순위·빌드 화면
4. 이미지 캐시·즐겨찾기·최근 조회
5. Windows 실행·종료·런타임 포함 배포 및 검증
6. GitHub Actions 검사·패키징·Release 워크플로와 첫 사전 릴리스 준비

## 요약의 주문·스킬 배치

요약 순서는 소환사 주문·스킬 순서 → 추천 증강 TOP 10 → 핵심 빌드 조합 3개다. 주문·스킬은 사용 빈도 기준으로 선택한 요약 빌드 유형의 상위 주문 조합 2개와 첫 스킬 순서를 사용한다. 주문에는 이미지·이름을, 스킬에는 레벨과 키를 표시한다. 데이터가 없으면 임의로 채우지 않는다. 주문·스킬은 요약에서만 표시하며 아이템 빌드 탭에서는 표시하지 않는다.

## 요약 추가 배치 조정

- 소환사 주문은 상위 두 조합을 가로 한 줄로 배치하고, 그 아래 레벨별 스킬 순서를 한 줄로 표시한다. 좁은 화면에서는 스킬 영역 안에서 가로 스크롤한다.
- 핵심 빌드 영역은 넓은 화면에서 좌우 두 열로 구성한다. 왼쪽은 사용 빈도 1순위 유형의 코어 조합 3개, 오른쪽은 2·3순위 유형의 첫 코어 조합을 각각 표시한다. 유형 이름을 함께 표시하고 추가 API 호출은 하지 않는다.
- 빌드 유형이 부족하면 있는 만큼만 표시하며, 첫 코어 조합이 없으면 누락 안내를 표시한다. 좁은 화면에서는 두 열을 위아래로 배치한다.

## 다크·라이트 모드

상단의 해·달 버튼으로 전환한다. 기본값은 다크이며 선택을 브라우저 및 로컬 설정 파일에 저장해 재실행과 포트 변경에도 유지한다. 기존 설정에 테마가 없으면 다크로 처리한다. 초기 화면은 브라우저 저장값을 먼저 적용해 새로고침 시 깜빡임을 줄인다. 테마 전환은 데이터 다운로드를 요청하지 않는다.

## 터미널 없는 실행 및 트레이

작은 Windows 실행기와 기존 로컬 웹 구조를 유지한다. WinForms NotifyIcon으로 상태와 화면 열기·로그 폴더 열기·서버 종료 메뉴를 제공하고 Node는 창 없이 실행한다. 동일 폴더의 실행기는 하나만 유지한다. 화면에서 종료하면 트레이도 닫고, 트레이 종료 시 서버까지 종료한다. 브라우저 탭만 닫으면 서버와 트레이는 유지한다. 서버 상태 확인은 로컬 요청만 사용한다.

실행기가 시작한 Node는 Job Object로 소유해 실행기 강제 종료 시 정리한다. 로그는 logs/launcher.log에 저장하고 최대 약 2MB에서 이전 로그 하나를 유지한다. 오류창에는 키나 응답 본문을 표시하지 않는다. 실행기는 .NET Framework를 사용하며 Node와 Chromium을 추가로 앱 안에 중복 포함하지 않는다. Node는 기존 동봉 런타임을 사용한다. 실제 Windows 10 트레이와 기본 브라우저 동작은 최종 실사용 확인이 필요하다.


## 신발과 아이템 빌드 분리

신발은 모든 빌드 유형에서 모아 중복을 제거하고 요약·아이템 빌드 탭에 각각 공통 영역으로 한 번 표시한다. 신발을 제외한 코어 조합은 원본 coreItemIds와 일치하는 step 1 후속 조합을 게임 수순으로 연결해 3개까지 채운다. 연결된 조합이 없으면 해당 빌드 유형의 후속 아이템을 사용 빈도순으로 보충하며, 이 경우 조합 승률·표본은 표시하지 않는다. 후속 데이터가 부족하면 있는 만큼만 표시한다. 연결 조합의 통계도 원본 신발 포함 표본에 기반하며 신발 단독 통계로 재해석하지 않는다. 원본 캐시는 수정하지 않고 추가 API 요청도 하지 않는다.

후속 아이템 영역은 해당 빌드 유형에서 실제 표시하는 상위 3개 핵심 조합의 아이템을 제외한다. 신발 대신 연결하거나 보충한 아이템도 제외하며, 화면에 표시하지 않는 4번째 이후 조합과 다른 빌드 유형은 제외 기준에 포함하지 않는다. 남은 후속 아이템이 없으면 영역을 숨긴다.


## 증강 능력 설명 툴팁

요약과 증강 순위의 증강 아이콘·이름에 마우스를 올리거나 키보드 초점을 두면 한국어 능력 설명을 표시한다. augments.json의 tooltip을 우선 사용하고 description을 대체값으로 사용한다. 기존 상세에 설명이 없으면 별도로 받은 증강 목록을 ID로 연결하되 챔피언별 통계는 덮어쓰지 않는다. 설명 데이터 버전을 툴팁에 표시하고, 미제공 수치는 추정하지 않는다. 제공자 태그는 텍스트로 변환하며 원격 HTML은 삽입하지 않는다.

증강 설명 받기 버튼은 필요한 경우 1 credit으로 목록을 받아 기존 augments.json 캐시에 저장한다. 같은 버전은 재사용하고 수집 중 버전 변경·실패 시 기존 캐시를 유지한다. 호버와 일반 조회는 캐시만 사용하며, 전체 증강 수집에서 이미 받은 설명도 재사용한다. Escape로 툴팁을 닫을 수 있다.


## 핵심 조합별 다음 아이템

아이템 빌드의 각 핵심 조합은 버튼으로 선택할 수 있다. 기본은 기존 공통 후속 목록이며, 조합을 선택하면 신발 포함 원본 코어 ID와 이미 표시한 후속 아이템의 순서가 일치하는 itemExtensions에서 바로 다음 아이템만 표시한다. 같은 다음 아이템은 중복 제거하며 더 가까운 단계와 표본 수순으로 정렬한다. 표시 조합이 같아 합쳐진 원본 경로도 모두 보존한다. 연결 데이터가 없으면 빈 상태를 명시하며 공통 목록으로 대신 채우지 않는다. 같은 조합 재선택 또는 공통 후속 보기로 선택을 해제한다. 선택은 빌드 유형별로 유지하며 정렬 변경으로 다른 유형에 옮겨가지 않고 챔피언·데이터 버전 변경 시 초기화한다. 추가 API 호출 없이 기존 캐시로 동작한다.

### 증강 도감

상단 `챔피언 / 증강 도감`에서 화면을 전환한다. 도감은 기존 증강 메타데이터 캐시를 재사용하고, 이름·초성 검색과 등급 필터를 함께 적용해 이름순으로 24개씩 표시한다. 선택한 증강의 설명과 상세 효과, 제공자의 `topChampions` 추천 목록을 아래에 표시한다. 추천 챔피언별 승률은 추정하지 않는다. 설명이나 추천 목록이 없으면 안내를 표시한다.

추천 챔피언을 누르면 기존 챔피언 화면으로 이동하며 저장된 상세만 조회한다. 도감 열기·검색·화면 이동은 유료 API를 자동 호출하지 않는다. 도감 다운로드 버튼은 기존 `/api/augment-descriptions/download` 경로를 사용하고 같은 버전의 설명이 있으면 재사용한다. API 키가 없어도 저장된 도감은 열람할 수 있다. 도감에서도 `/`로 검색창을 선택하고 Escape로 검색어를 지울 수 있다.

## 배포 파일 경량화

서버는 `scripts/build-server.mjs`에서 Node 22 대상 ESM으로 의존성까지 묶는다. CommonJS 의존성이 Node 내장 모듈을 읽을 수 있도록 `createRequire`를 제공하고, 빌드 결과의 외부 참조가 Node 내장 모듈뿐인지 검사한다. 서버·화면 의존성의 라이선스 고지는 `app/server/THIRD_PARTY_LICENSES.txt`에 보존한다.

Windows 배포 단계는 npm 설치를 수행하지 않고 묶은 서버, 화면 파일, 최소 package.json을 복사한다. 공식 Node ZIP의 체크섬을 확인한 후 node.exe와 LICENSE만 포함하며 npm·npx·node_modules·package-lock.json은 배포하지 않는다. 사용자 데이터는 기존처럼 문서/mayhem-pocket에 보관되어 배포 폴더와 독립적이다.

node_modules가 없는 별도 한글·공백 경로에서 묶은 서버의 시작, 정적 파일과 캐시 API, 설정 저장, 인증 없는 종료 거부, 정상 종료, 실행 기록 제거, 재실행과 설정 유지를 테스트한다. Windows CI는 생성한 ZIP을 새 폴더에 풀어 런타임 파일 목록과 node_modules 부재를 검사한 뒤 기존 GUI 실행기·중복 실행·웹 종료·종료.cmd·포트 충돌·강제 종료 검증을 수행한다. macOS의 서버 테스트 통과와 실제 Windows 패키지 검증 결과는 구분한다.

## v0.1.6 C# 전체 서버

Windows 정식 빌드는 CSHARP_SERVER로 실행기와 loopback 서버를 한 프로세스에 통합한다. 조회용 시제품은 과거 태그로 보존하며 정식 빌드는 기존 문서/mayhem-pocket 저장소를 사용한다. 자격 증명은 현재 사용자 ACL로 제한하고 상태 응답·로그에 반환하지 않는다. API/이미지 요청은 고정된 HTTPS 제공자와 CDN만 허용하고 리디렉션을 따르지 않는다. 헤더·본문·응답 크기, 동시 연결 수, 요청 수신 시간과 외부 요청 시간을 제한한다.

같은 버전의 다운로드를 생략하며 버전 재확인 후에만 버전별·현재 캐시를 원자적으로 저장한다. 전체 수집은 20 credits를 남기고 중단·재개하며 완료된 캐시를 재사용한다. 사용량은 키 해시와 UTC 날짜에 연결하고, 유료 응답 헤더가 없거나 연결이 끊겨도 요청 전 예상 비용을 보수적으로 기록한다. 설정·캐시 형식은 기존 Node 서버와 호환한다.

CSHARP_TEST는 별도 검증 실행 파일에만 정의한다. 검증 시 loopback 제공자와 짧은 요청 간격을 사용하고, 일반 배포 빌드에서는 테스트 주소·간격 설정을 컴파일에서 제외한다. Windows 검증은 실제 배포 바이너리의 실행·종료와 검증 바이너리의 새 환경 다운로드·사용량·중단·오류·버전 변경·이미지 캐시 처리를 모두 통과해야 한다.
