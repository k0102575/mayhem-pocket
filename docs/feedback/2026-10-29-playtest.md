# 2026-10-29 실사용 피드백 및 후속 작업

## 배경

v0.1.1을 Windows 게임용 PC에서 한 게임 동안 사용했다. 게임 진행에 문제는 없었고, 체감상 기존 통계 사이트보다 쾌적했다. 메모리 사용량은 측정하지 않았으므로 성능 개선을 수치로 확정하지 않는다.

사용 환경: Windows 10, RAM 16GB, Chrome, 단일 4K 모니터, Windows 배율 150%. 프로젝트 경로는 `/Users/p217811/me/mayhem-pocket`이며 이전 `opgg-clone` 폴더명에 의존하지 않는다.

이 문서는 실사용 요구사항과 인수 기준이다. 1~4번은 로컬 구현 및 검증을 완료했다. 5번 실행 방식은 논의 대기다. 오늘 확정한 UI와 예외 처리를 검증해 커밋하는 단계다. 다음 버전 번호와 배포 시점은 미정이며 배포는 별도 진행한다.

## 1. 스크롤바 표시 여부에 따른 화면 좌우 이동 방지

- 현상: 세로 스크롤바가 나타나거나 없어질 때 화면 너비와 콘텐츠 위치가 바뀐다.
- 방향: 실제 스크롤 컨테이너를 확인하고 `scrollbar-gutter: stable` 등으로 스크롤바 공간을 유지한다. 별도 스크롤 컨테이너도 점검한다.
- 인수 기준: 챔피언 선택, 탭 전환, 검색 결과 증감, 다운로드 상태 변경 전후에 검색창·상세 패널이 좌우로 움직이지 않는다. 불필요한 가로 스크롤이 생기지 않는다.
- 확인 위치: `src/style.css`.

## 2. 공백에 영향받지 않는 챔피언 검색

- 현상: `탐 켄치`를 `탐켄`으로 검색하면 결과가 나오지 않는다.
- 방향: 검색 대상과 검색어의 공백을 같은 규칙으로 제거하고 대소문자를 정규화한다. 기존 이름·부분 문자열·초성·별칭 검색을 유지한다.
- 인수 기준: `탐켄`, `탐 켄`, `탐켄치`, `탐 켄치`로 탐 켄치를 찾을 수 있다. `ㅌㅋ` 등 공백 없는 초성 검색도 동작한다. 빈 검색어는 전체 목록을 표시한다.
- 확인 위치: `src/App.tsx`의 `matches` 및 호출부. 공유 검색 함수를 추출한다면 의미 있는 회귀 테스트를 추가한다.

## 3. 첫 탭에 증강·아이템 요약 추가

- 요구: 첫 탭 이름을 `빌드`로 하고, 증강 순위 상위 10개 바로 아래에 핵심 빌드(아이템 조합) 최대 3개를 각각 아이템 이미지 한 줄로 표시한다. 아이템 3개가 아니라 조합 3개이며, 각 조합의 아이템을 3개로 자르지 않는다. 기존 탭은 이후 순서로 유지한다.
- 탭 순서: `빌드` → `증강 순위` → `아이템 빌드`.
- 제안 기본값: 첫 진입은 새 `빌드` 탭. 증강은 API 추천 rank 오름차순 상위 10개, 아이템 영역은 OP.GG처럼 핵심 빌드의 아이템 이미지 조합 3줄을 순서대로 배치한다. 사용 빈도 1위라는 문구나 큰 빌드 카드·통계는 요약에 표시하지 않는다. 어느 빌드의 아이템을 선택할지는 기존 기본 정렬을 내부 기준으로 재사용하되, 사용자에게 순위 기준이 새로 확정된 것처럼 안내하지 않는다.
- 요약 탭은 기존 증강 탭의 검색·등급 필터·정렬에 영향받지 않는 고정 요약으로 구성한다. 증강에는 아이콘·이름·순위와 유효한 통계 및 출처를 재사용한다. 핵심 빌드는 조합 3줄의 이미지를 기본으로 하고 접근성용 대체 텍스트와 마우스를 올렸을 때 이름을 제공한다.
- 기존 상세 탭의 전체 목록·필터·정렬을 유지한다. 빌드 데이터가 없으면 증강 요약은 표시하고 빌드 다운로드 안내를 제공한다. 추가 API 호출 없이 저장된 상세에서 계산한다.
- 증강과 빌드의 버전이 다를 때 기존 구버전·출처 안내를 유지한다. 일반 칼바람 빌드를 아수라장 전용 통계로 표현하지 않는다.
- 인수 기준: 탭을 오가지 않아도 상위 증강 10개와 핵심 빌드 조합 3줄을 연속해서 확인할 수 있다. 증강이 10개 미만이거나 핵심 빌드 조합이 3개 미만이면 있는 만큼 표시하고, 없는 아이템은 추측하지 않는다. 목표 Windows 배율에서 정보가 읽기 쉽고 불필요하게 큰 여백이 없다.
- 확인 위치: `src/App.tsx`, `src/style.css`, `server/cache-policy.ts`의 탭 설정 검증과 기존 설정 마이그레이션. 기존 tab 값은 유효하게 유지하고 새 사용자·새 기본 탭 정책을 일관되게 반영한다.

## 4. 상세 다운로드 진행 상태 강화

- 현상: 상세 받기 후 약 2~3초 동안 클릭이 반영됐는지 구분하기 어렵다.
- 현재 코드에는 공통 `busy`에 따른 `처리 중…` 문구가 있으나 실사용에서 충분히 인지되지 않았다. 단순히 로딩 문구가 없다고 단정하지 않는다.
- 방향: 상세 다운로드 대상과 작업 상태를 구분하고, 누르는 즉시 버튼에 로딩 아이콘·`상세 받는 중…` 문구를 표시한다. 중복 요청은 막고 기존 캐시는 계속 볼 수 있게 한다.
- 완료·실패 피드백을 명확히 표시한다. API가 진행률을 제공하지 않으면 가짜 퍼센트는 표시하지 않는다.
- 인수 기준: 느린 응답에서도 즉시 진행 상태를 알아볼 수 있고 완료·실패 후 정상 상태로 돌아온다. 다운로드 중 챔피언을 바꿔도 다른 챔피언에게 결과나 진행 상태가 잘못 붙지 않는다. 실패 시 기존 데이터가 유지된다.
- 확인 위치: `src/App.tsx`의 공통 `action`, `busy`, 상세 다운로드 핸들러 및 선택 챔피언 보호 로직.

## 5. 터미널 창 없는 실행 방식 논의

- 현상: 로컬 서버 실행 중 터미널 창이 떠 있는 점이 불편하다.
- 이 항목은 방향 결정이 필요하다. 웹 배포나 Electron 전환을 확정하지 않았다.
- 우선 제안: 로컬 웹 구조를 유지하면서 콘솔 창 없는 Windows 실행기와 명확한 종료 수단을 검토한다. Node 런타임 동봉·별도 설치 없음이라는 기존 목표를 유지한다.
- 검토할 사항: 백그라운드 실행·중복 실행 방지·브라우저 열기·서버 종료·오류 확인용 로그·한글 및 공백 경로·Windows 보안 알림과 배포 복잡도.
- 웹 배포를 비교한다면 API 키 보관, 사용자별 할당량, 서버 비용, 캐시 및 이미지 저장, 데이터 제공자 이용 조건을 먼저 검토한다. 공개 프런트엔드에 API 키를 넣는 방식으로 해결하지 않는다.
- 현재 터미널 창 하나가 불편하다는 이유만으로 웹 서버 배포가 필수인 것은 아니다. 앱 패키징은 메모리 부담과 관리 비용까지 비교한다.
- 인수 기준과 최종 구현 범위는 실행 방식 논의 후 확정한다. 앞의 UI 개선과 독립적으로 진행 가능하다.

## 진행 제안 및 검증

1. 1~4번을 다음 UI 개선 묶음으로 구현한다. 3번의 순위·기본 탭 정책은 위 제안값을 기본으로 삼는다.
2. 기존 자동 테스트와 빌드를 실행하고, 공백 검색·탭 설정·다운로드 중 챔피언 변경에 대한 필요한 회귀 검증을 수행한다.
3. Windows Chrome에서 스크롤바 유무, 화면 배율 150%, 다운로드 지연·실패 상황을 확인한다. Mac 검증으로 Windows 실사용 확인을 대체하지 않는다.
4. 5번은 옵션과 장단점을 사용자에게 설명한 뒤 실행 방식을 정한다.
5. 배포 요청 시 새 버전을 정하고 `docs/releases/버전.md`에는 이번 변경과 검증 결과만 작성한다. 사용법은 README에서 관리한다.

## 구현 및 검증 기록

- 공백·초성·영문 별칭 검색 정규화, 루트와 내부 스크롤 영역의 스크롤바 공간 유지.
- 빌드 요약 탭: 추천 증강 최대 10개, 넓은 화면에서 5개씩 두 열, 아래에 코어 빌드 조합 최대 3개를 각각 이미지 한 줄로 표시. 기존 탭의 필터와 독립적이며 기존 탭 선택 설정은 유지.
- 상세 다운로드 대상별 로딩 아이콘·안내 및 완료·실패 피드백. 요청 중 챔피언 변경 시 결과가 다른 챔피언을 덮지 않는지 검증.
- 빌드 및 자동 테스트 15개 통과. 임시 Chrome에서 모의 API로 검색, 요약, 기존 탭, 다운로드 지연·실패·선택 변경을 검증했다. 실제 API credits는 사용하지 않았다.
- 실제 Windows Chrome의 기본 스크롤바와 150% 배율은 사용자 PC에서 최종 확인이 필요하다. 터미널 없는 실행 방식은 변경하지 않았다.

## 추가 UI 정리: 다운로드 기록

- 상세 상단에 마지막 다운로드 시각을 한 번만 표시한다.
- 통계 기준일·제공자 생성·빌드 패치와 출처는 기본으로 접힌 데이터 정보에 모은다.
- 증강과 빌드 버전이 다를 때만 이전 빌드 사용 안내를 노출하고, 이전 빌드의 버전과 다운로드 시각은 접힌 정보에서 확인한다.
- 핵심 빌드 아래의 중복 날짜를 제거한다. 목록·API 확인 기록도 기본으로 접힌 별도 정보로 정리한다.

## 추가 개선: 챔피언 목록 자체 티어

- 목록에는 S/A/B/C/D 배지만 표시하고 승률 숫자는 숨긴다. 빠른 선택을 위해 상세 화면에서만 승률을 확인한다.
- 전체 목록의 유효한 승률 순위를 기준으로 S 상위 10%, A 10~30%, B 30~70%, C 70~90%, D 하위 10%로 나눈다. 검색과 즐겨찾기에 따라 재계산하지 않는다.
- 같은 승률은 같은 높은 순위를 부여한다. 따라서 동률과 적은 챔피언 수에서는 구간별 인원이 정확한 비율과 다를 수 있다. 승률 누락·무효는 티어를 계산하지 않고 —로 표시한다.
- 제공자 공식 티어와 구분해 승률 기준 자체 티어라고 안내한다. API 호출은 추가하지 않는다.

## 화면 전체 정보 정리

- 큰 소개 문구를 제거하고 데이터 관리에 목록·버전 확인·전체 수집·credits·아이콘 재다운로드를 모아 기본으로 숨긴다.
- 목록에는 아이콘·이름·티어를 표시하고 별칭과 이동 화살표를 제거한다. 최근 조회와 즐겨찾기는 유지한다.
- 상세 헤더는 아이콘·이름·즐겨찾기·상세 버튼만 표시한다. 영문 이름·별칭·API 숫자 티어를 숨기고 챔피언 승률은 접힌 데이터 정보로 이동한다.
- 상세 최신 여부는 다운로드 시각 옆에 한 번 표시한다. 현재 챔피언 다운로드는 버튼 로딩만 표시하고, 다른 챔피언을 보는 동안에만 다운로드 대상 안내를 별도로 표시한다.
- 요약 증강은 순위·아이콘·이름·등급만 표시하며 승률·표본은 증강 순위 탭에 유지한다.
- 빌드 출처는 각 빌드 카드마다 반복하지 않고 해당 영역에서 한 번 안내한다.
- 성공 알림과 전체 수집 완료 메시지는 4초 후 숨긴다. 오류·중단·제한 및 이전 빌드 안내는 유지한다.

## 화면 정리 후 사용자 보정

- 소개 영역의 “다음 선택을, 조금 더 쉽게.” 문구와 설명은 유지한다.
- 목록 확인·갱신과 전체 증강 받기는 소개 영역 옆에 항상 표시한다. 관리 영역에 감춰 기능을 찾기 어렵게 하지 않는다.
- 상세 확인 버튼 옆에 챔피언 승률을 표시한다. 목록은 자체 티어만, 상세는 승률만 표시하며 상세의 접힌 정보에 승률을 반복하지 않는다.
- 나머지 버전·credits·세부 기록·아이콘 재다운로드는 데이터 관리에서 유지한다.

## 요약의 주문·스킬 배치

요약 순서는 소환사 주문·스킬 순서 → 추천 증강 TOP 10 → 핵심 빌드 조합 3개다. 주문·스킬은 사용 빈도 기준으로 선택한 요약 빌드 유형의 상위 주문 조합 2개와 첫 스킬 순서를 사용한다. 주문에는 이미지·이름을, 스킬에는 레벨과 키를 표시한다. 데이터가 없으면 임의로 채우지 않는다. 아이템 빌드 탭의 유형별 주문·스킬은 접힌 영역에 유지한다.

## 요약 추가 배치 조정

- 소환사 주문은 상위 두 조합을 가로 한 줄로 배치하고, 그 아래 레벨별 스킬 순서를 한 줄로 표시한다. 좁은 화면에서는 스킬 영역 안에서 가로 스크롤한다.
- 핵심 빌드 영역은 넓은 화면에서 좌우 두 열로 구성한다. 왼쪽은 사용 빈도 1순위 유형의 코어 조합 3개, 오른쪽은 2·3순위 유형의 첫 코어 조합을 각각 표시한다. 유형 이름을 함께 표시하고 추가 API 호출은 하지 않는다.
- 빌드 유형이 부족하면 있는 만큼만 표시하며, 첫 코어 조합이 없으면 누락 안내를 표시한다. 좁은 화면에서는 두 열을 위아래로 배치한다.

## 다크·라이트 모드

상단의 해·달 버튼으로 전환한다. 기본값은 다크이며 선택을 브라우저 및 로컬 설정 파일에 저장해 재실행과 포트 변경에도 유지한다. 기존 설정에 테마가 없으면 다크로 처리한다. 초기 화면은 브라우저 저장값을 먼저 적용해 새로고침 시 깜빡임을 줄인다. 테마 전환은 데이터 다운로드를 요청하지 않는다.

## 최종 예외 처리 점검 및 보완

- 상세 조회 실패 시 로딩 안내를 종료하고 상세 다시 시도 버튼을 제공한다. 이미 보이는 캐시는 유지하며 챔피언 변경과 요청 순서를 검증해 이전 응답이 현재 상세를 덮지 않게 한다.
- 설정 읽기 실패 시 현재 브라우저 선택을 유지하고 재시도 버튼을 제공한다. 읽기 복구 후 저장을 재개한다. 저장 실패에도 별도 다시 저장 버튼을 제공한다.
- 초기 설정 로딩 중 사용자가 변경한 항목은 늦게 도착한 파일 설정으로 덮지 않는다. 변경하지 않은 항목은 저장된 값을 복원한다.
- 초기 최신 버전 확인 실패 시 별도 오프라인 알림을 추가하지 않고 하나의 상태 안내로 표시한다.
- 키보드 챔피언 선택은 이번 작업에 추가하지 않는다. 터미널 없는 실행 방식은 별도 논의한다.

## 최종 검증 결과

- 프로덕션 빌드와 회귀 테스트 19개 통과.
- 실제 블라디미르 캐시를 사용하는 임시 Chrome에서 상세 읽기 실패 후 재시도, 설정 읽기·저장 실패 후 복구, 지연된 초기 설정과 사용자 변경의 충돌 방지를 확인했다.
- 설정 복구 시 사용자가 바꾼 테마·챔피언은 유지하고, 바꾸지 않은 즐겨찾기·탭 등은 파일 값을 복원하는 것을 확인했다.
- 오프라인 안내는 한 곳에만 표시된다. API 다운로드 호출이나 키 노출 없이 검증했다.
- 실제 Windows 10 Chrome의 최종 실사용 확인과 터미널 없는 실행 방식은 남아 있다.
