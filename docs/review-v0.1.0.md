# v0.1.0 전체 검토

검토일: 2026-10-28. 대상: 공개된 v0.1.0 구현. 이번 작업은 검토이며 기능 수정·재배포는 수행하지 않았다. 실제 ARAMGG 통계 API 추가 호출 없이 코드와 임시 캐시·로컬 서버로 확인했다.

## 우선 수정할 결함

### P1. 새 상세보다 이전 원시 캐시가 선택됨 — 재현 확인

server/index.ts:127의 상세 조회는 최신 여부보다 catalog 버전 일치를 우선한다. catalog와 raw가 old이고 full이 new인 경우, full을 새로 받아도 다음 조회에서는 old raw를 반환한다. 임시 캐시로 old 선택·빌드 0개 반환을 재현했다. 사용자가 상세를 받은 뒤 다른 챔피언으로 이동했다 돌아오면 새 상세와 빌드가 사라진 것처럼 보일 수 있다.

대책: 버전이 다른 캐시의 선택 정책을 통일하고, 최신 증강과 이전 빌드를 구분해 보존한다. catalog 버전만으로 새 full을 밀어내지 않는다. 새 상세 다운로드, 챔피언 이동, 재실행 회귀 검증을 추가한다.

### P1. 전체 동기화가 이전 버전 표기로 새 데이터를 저장할 수 있음 — 코드 경로 확인

server/index.ts:175는 catalog.meta.dataVersion을 수집 목표로 쓰지만 요청 URL은 항상 현재 데이터를 반환한다. catalog를 먼저 갱신하지 않으면 실제 데이터와 저장 메타가 다를 수 있다. 오래된 raw가 이미 있으면 최신 remote를 알고도 다운로드를 전부 건너뛴다. 수집 중 공급자 버전이 바뀌는 경우도 확인하지 않는다.

대책: 동기화 전에 무료 config로 목표 버전을 확정하고 필요한 목록·기본 정보의 버전을 일치시킨다. 완료 전 버전을 재확인하고 불일치 결과를 잘못된 버전으로 활성화하지 않는다. 버전별 저장 공간을 사용한다.

## 사용성·상태 표시

### P2. 최신 버전은 조회하지만 업데이트 안내가 없음

server는 remoteVersion을 반환하지만 UI가 이를 사용하지 않는다. src/App.tsx:475의 이전 버전 표시는 catalog와만 비교하므로 remote가 새로워져도 저장 데이터가 최신처럼 보일 수 있다.

대책: 최신/업데이트 있음/최신 여부 확인 불가를 구분하고 무료 버전 재확인 버튼과 마지막 확인 시각을 제공한다. 최신 캐시를 이전 버전으로 오표시하지 않는다.

### P2. 로컬 다운로드 시각과 통계 기준일이 없음

save는 downloadedAt을 기록하지 않고 화면에는 패치·버전만 표시한다. upstream generatedAt 또는 stats.date는 로컬 저장 시각과 다르다.

대책: 목록·증강·빌드마다 downloadedAt을 기록하고 제공자의 기준일과 함께 표시한다. 기존 캐시는 시각 미기록으로 처리하며 시각을 임의 생성하지 않는다.

### P2. 목록 갱신이 매번 1 credit 사용, 상세 버튼은 캐시 반환도 2로 표기

server/index.ts:114는 같은 버전 목록을 재요청한다. 상세 API는 같은 버전을 재사용하지만 화면의 상세 받기 · 2 문구는 변하지 않는다. 전체 동기화 전 예상 요청 수·비용도 표시하지 않는다.

대책: 무료 버전 확인과 유료 다운로드를 구분하고 최신/다운로드 필요/다운로드 중/저장됨 상태를 버튼에 표시한다. 전체 수집 예상 비용과 잔여 예산을 먼저 안내한다. 실패 원인별 메시지도 개선한다.

### P2. 전체 수집 진행 시 현재 증강 검색이 초기화됨

src/App.tsx:143~155는 job.done이 바뀔 때마다 detail을 비우고 AQ('')를 수행한다. 진행 상태는 약 1.8초마다 갱신되므로 수집 중 검색·비교를 방해한다.

대책: 검색 초기화는 챔피언 변경 시에만 수행한다. 새 데이터는 현재 화면과 입력을 유지하며 교체한다.

### P2. credits가 키에 연결되지 않고 확인 시각이 없음

credits.json은 일자와 잔량만 저장한다. 같은 날 키를 바꾸면 이전 키의 잔량 0 때문에 새 키 요청도 로컬에서 차단될 수 있다. 다른 PC·앱에서 사용한 잔량은 현재 화면에 반영되지 않는데도 당일 마지막 응답이 있으면 잔여로만 표시한다.

대책: 원문 키를 저장하지 않는 식별값으로 기록을 분리하고 마지막 확인 시각을 표시한다. 실제 잔량 응답이 최우선이고 429 시 제한 원인을 구분한다.

### P2. 즐겨찾기가 포트 변경 시 사라진 것처럼 보임

localStorage는 브라우저 origin별 저장이다. 4318 충돌 시 4319로 이동하면 즐겨찾기·최근 조회·마지막 선택이 공유되지 않는다. 서버의 빈 포트 재시도는 실제로 성공하는 것을 확인했다.

대책: 설정을 로컬 서버 파일에 저장하고 기존 localStorage 값을 이전한다. 브라우저를 바꾸거나 배포 폴더를 업데이트해도 일관된 설정을 사용한다.

## 이미지와 배포

### P2. 이미지 캐시 갱신·복구 정책 부족

동일 URL은 영구 재사용하고 자동 정리·손상 복구가 없다. PNG/JPEG/WebP를 받지만 응답 MIME은 항상 image/png다. Icon 컴포넌트의 bad 상태는 url이 바뀌어도 초기화되지 않아 이전 이미지 실패가 새 챔피언 초상화까지 영향을 줄 수 있다.

대책: MIME과 저장 시각을 보관하고 URL 변경 시 실패 상태를 리셋한다. 이미지 재시도·캐시 정리 기능은 통계 재다운로드와 분리한다.

### P2. Windows CI가 실제 실행.cmd/종료.cmd 경로를 검사하지 않음

scripts/verify-package.mjs는 node.exe로 서버를 직접 실행하고 HTTP로 종료한다. 실제 --open, 기본 브라우저 열기, 실행.cmd 중복 실행, 종료.cmd, 한글·공백 경로의 더블클릭 흐름은 이 검사에 포함되지 않는다. 이는 확인된 실행 오류가 아니라 검증 공백이다.

대책: Windows CI에서 배포 ZIP을 새 한글·공백 경로에 풀고 스크립트 실행·중복 실행·종료를 검사한다. 실패 메시지가 바로 닫히지 않게 하고 Windows 10 실제 PC 검증은 별도 기록한다.

## 후순위

- rawDetail은 원시 응답의 augment_trios를 버려 전체 증강 수집만으로는 조합을 표시하지 못함.
- 빌드를 승률순으로 바꿔도 사용 빈도순이라는 고정 문구가 남음.
- API 티어 숫자는 공개 의미 확인 후 사용자에게 이해하기 쉬운 표기로 개선.
- 빈 데이터/키 오류/통신 실패/로컬 서버 종료를 더 구체적으로 구분.
- 업데이트 때 여러 폴더를 수동 교체하는 절차를 사용자 파일 보존형 스크립트로 단순화.
- 메모리 사용량은 실제 Windows 게임 병행 환경에서 측정해야 함. 현재 수치 보장 없음.

## 검증 범위와 양호한 부분

- 임시 캐시로 새 상세가 이전 원시 캐시에 가려지는 오류 재현.
- 동일 포트 점유 상황에서 다음 포트로 실행 성공 확인.
- 기존 빌드·3개 테스트·Windows 패키지 서버 실행/종료 성공은 기본 경로 검증이며 갱신·429·버전 전환까지 검증한 것은 아님.
- API 키를 프런트엔드에 전달하지 않고 loopback 바인딩, 변경 요청의 Origin/세션 토큰 검증 적용.
- 키·데이터·이미지·백업을 Git과 배포 ZIP에서 제외.
- 잘못된 승률을 그대로 표시하지 않고 파일 단위 임시 저장 후 교체.

## 제안 순서

1. 버전·캐시 선택·전체 수집 일관성 결함 수정.
2. 다운로드 시각·기준일·업데이트 안내·예상 비용을 한 흐름으로 정리.
3. 검색 입력 보존·credits 식별·설정 보존·이미지 복구 개선.
4. 실제 Windows 실행 스크립트와 버전 전환/중단/429 회귀 검증 후 새 사전 릴리스.

## 코드 수정 반영 (미배포)

- 캐시 선택을 버전 비교로 통일하고 새 증강과 이전 빌드의 메타데이터를 분리했다.
- 목록·기본 증강·원시 수집의 목표 버전을 맞추고, 원시 응답 저장 전 무료 config를 재검증한다. 중간 버전 변경이나 429 시 기존 캐시를 보존한다.
- JSON 다운로드 시각을 별도로 저장하며, 기존 파일에 시각이 없으면 미기록으로 표시한다. 챔피언 기준일·증강 승률 기준일·제공자 생성 시각을 구분한다.
- 최신 여부와 재확인 버튼, 같은 버전 캐시 재사용, 전체 수집 비용 안내를 추가했다. 최신 상세가 이미 있으면 원시 요청도 건너뛴다.
- 진행률 변경 시 검색 입력을 초기화하지 않는다. 취소 후 대기 중인 유료 요청도 실행하지 않는다.
- credits를 원문 키가 아닌 SHA-256 식별값과 UTC 날짜로 구분하고 마지막 확인 시각을 표시한다.
- 설정은 cache/settings.json으로 옮겨 포트와 무관하게 유지하며 기존 브라우저 설정을 처음 한 번 이전한다.
- 이미지 URL 변경 시 실패 상태를 초기화하고 실제 MIME을 보존하며 아이콘만 다시 받을 수 있다. 자동 용량 정리 정책은 후순위로 남는다.
- 원시 응답의 증강 조합을 보존하고 빌드 정렬 안내를 선택값과 일치시켰다.
- Windows 패키지 검사를 ZIP 추출·한글/공백 경로·실행.cmd·중복 실행·종료.cmd 경로로 확장했다. 코드 작성과 문법 검사까지 완료했으며 새 Windows CI 실행·실제 브라우저 열기·Windows 10 게임 병행 메모리 검증은 아직 수행하지 않았다.
- 로컬 프로덕션 빌드 및 12개 테스트 통과. 버전 혼합, 키/UTC 날짜별 credits, 설정의 다른 포트 보존, 같은 버전 무과금 재사용, 버전 변경/429 시 캐시 보존, 중단·재개를 모의 API로 검증했다. 실제 통계 API 추가 credits 사용 없음.
- 사용자 파일 보존형 자동 업데이트와 API 티어 숫자의 사용자용 매핑은 별도 후속 작업이다. 이번 변경은 커밋·push·릴리스하지 않았다.
